# Discord認証と利用ユーザー管理

閲覧・管理ともDiscord OAuthでログインします。サイト独自のパスワード入力・再設定はありません。Discordアカウントの認証情報はDiscord側で管理します。

## 初期設定

- `DISCORD_CLIENT_ID`、`DISCORD_CLIENT_SECRET`、`DISCORD_REDIRECT_URI`を設定します。Discordアプリ側にも同じcallback URLを登録してください。
- Web管理者は`ADMIN_USER_ID`または`WEB_ADMIN_USER_IDS`で1人以上指定します。後者はBotの権限を変更しません。
- 閲覧者は`DISCORD_ALLOWED_USER_IDS`または管理画面で許可します。管理者には閲覧権限もあります。
- `ALLOW_ANONYMOUS_READ`はfalseです。旧`WEB_PASSWORD`・`ADMIN_PASSWORD`が残ってもパスワードではログインできません。
- Discord障害時は新規ログインできません。唯一の管理者がアカウントを失った場合、サーバ設定から別のDiscord管理者を指定して復旧します。

## 管理画面

`/admin/users`の「＋ ユーザー追加」から一覧に入力行を開き、Discord IDと権限を選んで保存します。既存ユーザーは編集アイコンから同じ入力行を開き、保存またはキャンセルします。権限は「閲覧」「管理者」です。削除アイコンは利用許可を取り消します。登録元や実行者は一覧に並べず、監査に残します。IDは17〜20桁の半角数字、先頭ゼロなし、uint64上限以下の文字列です。Discordユーザー名ではなくユーザーIDを指定してください。

IDと権限の変更は一括で保存し、登録日時を保持します。追加済みIDへの変更と初期設定で固定されたユーザーの画面変更は拒否します。固定ユーザーは「初期設定で固定」と表示します。サーバ設定で管理するIDの権限を優先し、画面から追加した管理者はWebの管理権限を持ちます。Botの管理者設定は変わりません。

操作はCSRF保護と管理者確認を行い、読取専用モードでは拒否します。取消後の既存セッションは次のリクエストから拒否します。同じIDを再追加しても、旧Cookieは許可の世代値が異なるため復活しません。追加・変更・削除の実行者と操作種別、変更前後の権限を監査へ保存します。ID・権限の変更では許可の世代値を更新し、旧管理セッションも失効させます。再昇格しても旧管理Cookieは復活しません。変更なしの保存はセッションを失効させません。権限・セッション失効・監査は同じDBトランザクションで確定します。保存後は一覧のGETへ戻り、再読み込みで操作を再送信しません。

## セッションとDB移行

管理者セッションはDB照合・発行から24時間の絶対期限・ログアウト時の失効を維持します。サーバ設定の管理者とDBに保存した管理者の権限を毎回照合します。権限を下げたユーザーの管理セッションは拒否します。旧パスワードでのCookieと管理者セッションは無効です。

migration `20261006_01`で閲覧許可の世代値と監査の操作種別・訂正先IDを追加します。既存許可は保持し、移行後は閲覧者もDiscordで再ログインします。店舗・元投稿・既存操作履歴は保持します。migration `20261006_02`で保存するWeb管理者権限と権限変更監査を追加します。既存のDB許可は閲覧のまま保持し、管理者へ自動昇格させません。変更監査や保存した管理者権限のあるDBのdowngradeは、記録損失や管理権限の喪失を防ぐため拒否します。

本番適用前にDBバックアップを取得し、OAuth設定と管理者IDを確認してからmigration・リリースを行ってください。ローカル検証では本番DBを変更しません。
