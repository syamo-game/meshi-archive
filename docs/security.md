# 認証と公開時の設定

## 秘密情報と実データ

秘密情報は環境変数または権限を制限した`.env`で管理します。`.env.example`だけを共有し、実際のパスワード・APIキー・DB・投稿・店舗写真はコミットしません。GitとDockerの除外設定は誤混入を減らしますが、公開前には対象ファイルそのものを確認してください。

## Webを外部公開する場合

本番用のCompose、プロキシ設定、デプロイ処理は同梱していません。実行環境に合わせて用意してください。

| 設定 | 条件 |
| --- | --- |
| `APP_ENV` | `production` |
| `SECRET_KEY` | 32文字以上のランダム値 |
| `WEB_PASSWORD` | 16文字以上 |
| `ADMIN_PASSWORD` | 24文字以上。ランダム値を推奨 |
| `HTTPS_ONLY` | `true` |
| `ALLOW_ANONYMOUS_READ` | `false`または未指定 |
| `FORWARDED_ALLOW_IPS` | リバースプロキシの実際の接続元IP |

不足・短いパスワード・HTTP用設定では起動を拒否します。プロキシはHTTPSを提供し、外部から受け取った転送ヘッダーを検証してからWebへ渡す必要があります。全接続元を信頼する`*`の代わりに、プロキシのIPを明示してください。Webポートへの直接接続も制限します。

Botには`DISCORD_TOKEN`と17〜20桁の`ADMIN_USER_ID`が必要です。利用者IDが未設定の場合はコマンドを処理しません。

## ログイン試行制限

閲覧・管理のそれぞれで、接続元ごとの失敗をDBに記録します。5回目の失敗で30秒、以後は60秒、120秒と延長し、最大300秒待機します。成功または15分の経過で回数をリセットします。待機中はHTTP 429と`Retry-After`を返し、DB保存に失敗した場合はログインを成立させずHTTP 503を返します。

IPや入力パスワードそのものは保存せず、ログイン種別と接続元のHMACを保存します。IPv6は同じ/64ネットワークで共有します。同じNAT配下の利用者も制限を共有するため、多数の接続元を使う攻撃への対策は別途必要です。

## CIと依存関係

`constraints.txt`で実行時の依存関係を固定しています。更新時は全テストとpip-auditを実行します。OSパッケージやPython本体はpip-auditの対象外です。

CIの権限は`contents: read`だけです。本番用のSecrets、SSH接続、コンテナの発行は使いません。外部PRのコードはテスト環境で実行されるため、本番資格情報を渡さない構成を維持してください。

Gitleaksは標準ルールを有効にし、既知のエラーメッセージとテスト用画像ハッシュだけを、ファイル名と正確な行内容の組み合わせで除外します。テストディレクトリ全体を除外する代わりに、必要な例外を限定しています。設定は[Gitleaksの公式仕様](https://github.com/gitleaks/gitleaks/blob/v8.30.1/README.md#configuration)に従います。

公開先のGitHubでは、PR・CI成功を必須とするmain保護、Secret scanning、push protection、Dependabot、外部PRの実行承認を確認してください。Git履歴を持ち込まない場合でも、新しいコミットの作者情報と公開対象のファイルは確認が必要です。

## バックアップ

店舗DBと画像保存先を組にしてバックアップします。CSVには画像本体が含まれないため、CSVだけでは写真を復元できません。スキーマ変更前は書き込みを停止し、バックアップからの復元を確認してから更新してください。
